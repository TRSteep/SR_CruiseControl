# Scaleform — экспериментальный прототип нативной строки

## Нативный автопилот 10: отдельная штатная подсказка клавиши

`build.ps1 -Autopilot` собирает `SnowRunnerNativeAutopilot.asi`; `-Autopilot -Package` дополнительно создаёт отдельный ZIP. Это вариант без DirectX/ImGui-наложения и без распознавания картинки. В штатном контейнере создаётся «АВТОПИЛОТ» на один шаг (48 единиц) выше ручника. Состояние меняется через Scaleform: выключено — серое, включено — жёлто-зелёное, ошибка ввода — красное. Клавиша F6 отображается отдельно справа в штатном `MC_PC` с полем `textField`. Используется авторский слот `buttonAttach` строки: x=207, y=8, масштаб 0.75; размеры, фон и шрифт берутся из игры. Унаследованный значок ручника скрыт. Настройка ToggleKey меняет также текст отдельной клавиши.

Перед установкой закройте игру. Уберите `SnowRunnerScaleformProbe.asi` и старый `SnowRunnerAutopilot.asi`, затем скопируйте `SnowRunnerNativeAutopilot.asi` и `SnowRunnerNativeAutopilot.ini` рядом с EXE. Совместимый ASI-загрузчик уже должен быть установлен. Не запускайте отдельную EXE-утилиту одновременно. Для удаления достаточно закрыть игру и убрать новый ASI/INI; загрузчик других модов не удалять.

F6 включает/выключает полный газ. W передаёт газ водителю, S/N отключают удержание. Esc/Enter/M/F1/F4 и потеря фокуса также отключают его. Это прежний `CruiseState`, а не регулирование скорости. F6 опрашивается независимо от низкоуровневого hook; физический W распознаётся через hook и оконный обработчик, собственный SendInput помечен. Назначения предполагаются W/S/N; геймпад/руль пока не отслеживаются.

Для включения нужна свежая (до 500 мс) проверка видимого HUD: строка прикреплена к сцене, родитель и его предки visible=true и alpha>0.01. Отсутствие свежего HUD блокирует новое включение, но само по себе не отменяет уже активное удержание; F6/W/S/N и потеря фокуса продолжают отменять его. Смена состояния и UI-проверка идут в Movie::Advance, клавиатурный поток публикует атомарное состояние и не вызывает Scaleform.

Movie::Advance найден в живой таблице Movie по индексу 24, RVA `0x19960B0`; параметры float delta / unsigned catchUp / bool capture и float-результат проверены по коду и автономному тесту передачи. Удаляющий деструктор Movie — vtable[0], RVA `0x19A1730`. Перед оригинальным деструктором освобождаются сохранённые управляемые ссылки панели/строки через ObjectInterface Release. Ссылки создаются через подтверждённый AddRef (`0x1B5D070`). Реестр не удерживает свою блокировку во время get/set AS3. Каждая строка выделяется отдельно и хранится через shared_ptr: вектор копирует только указатели, зарегистрированные GFx Value не перемещаются. На один Movie хранится не более 16 строк. Все новые адреса также защищены точным хешем EXE и префиксами инструкций.

В версии 8 обнаружена ошибка стабильности адресов. Первые 16 байт Value — связи intrusive-списка управляемых значений, а не свободные служебные поля: AddRef вставляет адрес Value в список ObjectInterface, Release удаляет именно этот адрес. Побитовое копирование зарегистрированного Value в другой элемент вектора или передача владения через присваивание нарушали список. Версия 9 использует неперемещаемые Owned, клонирование только полезной нагрузки в конечный адрес с новым AddRef и стабильные heap-записи. Регрессионный тест моделирует регистрацию адресов и отклоняет старую реализацию; исправленная проходит. В тесте проверяются также рост/вытеснение реестра и смена родителя при обходе дерева.

Журнал — `SnowRunnerNativeAutopilot.log`. В нём есть `Native frame hooks`, `Native input thread started`, `CONTROL-ON/OFF/ERROR` и heartbeat `Native frames=... HUD=... state=...`. При F6, заблокированной отсутствием HUD, записывается причина. `UI-keybadge.end` сообщает результат создания отдельной клавиши. Отказ загрузки этого символа не отключает работу основной строки и контроллера.

Проверено в игре пользователем: нативное движение/скрытие/возврат с картой (версия 7); загрузка, F6, S, W, N, Alt+Tab и смена подсветки (версия 9); правильное оформление/расположение отдельного квадратика F6 и его сохранение при переключении (версия 10). Проверенная сборка 10 выпускается как ingame-v1.1.0. Инструкция для готового релиза — `ingame/INSTALL_NATIVE.md`.

Настройки: `[Autopilot] Enabled=1`, `ToggleKey=117` (F6). Допустимы F2–F12, кроме F4. После изменения нужен перезапуск. Отключение движка мышью не определяется: отмена по N относится к физической клавише.

## Диагностическая версия 7

Отдельный диагностический ASI. Не содержит управления газом и не рисует DirectX-наложение. Версия 7 по умолчанию только наблюдает за созданием Flash-объектов и собственными чтениями HUD игрой. При `EnableTestRow=1` пытается создать TEST после штатного чтения `brakeBtn`, а не из callback создания HUD. Вызовы методов AS3 через Invoke исключены: в живом тесте версии 5 загрузка не завершила вызов `getChildByName`. В версии 6 игра загрузилась, создание пустого Sprite и изменение его свойств прошли, но добавление `hudBtnBg` в него вернуло false. Версия 7 вместо этого добавляет целый `hudBrakeBtn` прямо в существующую правую панель, заменяет label/текст на TEST и скрывает унаследованные значок ручника и подсказку клавиши. Для своей строки отключаются мышь и tab-фокус. Игровые обработчики ручника не регистрируются. Совместимость проверяется поэтапно.

Поддерживает только EXE с SHA256 `a3cb442ec138eb2eb7e335e5c80e376766550740e49e233ac9eace035e182285` (исследуемая Epic 44.1). Перед установкой перехватов проверяет весь EXE и префиксы обеих функций. При несовпадении записывает причину в журнал и ничего не перехватывает.

## Сборка и проверка

Из корня репозитория:

```powershell
.\ingame\experimental\scaleform\build.ps1
```

Для сборки отдельного ZIP используйте `build.ps1 -Package`. Архив `ingame/build/scaleform-probe/SnowRunner-Scaleform-Prototype-v7.zip` содержит ASI, INI с выключенным TEST, инструкцию и лицензию MinHook. Скрипт сборки ничего не устанавливает и не запускает игру.

Выход: `ingame/build/scaleform-probe/SnowRunnerScaleformProbe.asi`. Сборка запускает проверки чтения строк, недоступных адресов, передачи всех аргументов/результатов и неизменности наблюдаемых значений.

При закрытой игре скопируйте ASI и `SnowRunnerScaleformProbe.ini` рядом с SnowRunner.exe; нужен уже установленный ASI-загрузчик. С `EnableTestRow=0` мод только собирает журнал, без TEST. Чтобы позднее проверить нативную строку, поменяйте значение на `1` и перезапустите игру. Выберите «Продолжить» и дождитесь вида машины с автомобильным HUD. Достаточно стоять на месте. Строка TEST при успешном создании находится на два шага выше ручника, над рабочей планкой автопилота.

Если игра вообще не вызывает GetMember для `brakeBtn`, попытки создания не будет: после сообщения `TEST-await-brake-read` в журнале не появится `TEST-result`. Это означает, что потребуется другая точка подключения; отсутствие TEST само по себе не доказывает ошибку построения.

Журнал: `SnowRunnerScaleformProbe.log` рядом с EXE. После диагностики закройте игру и удалите `SnowRunnerScaleformProbe.asi` и `SnowRunnerScaleformProbe.ini`; рабочий мод и загрузчик сохраняются. На лету DLL не выгружать.

Журнал содержит имена Flash-символов, идентификаторы потоков и адреса объектов только текущего процесса. Адреса действительны лишь в пределах одного запуска. Игровые объекты и ссылки между событиями не удерживаются. Запись файла выполняется выделенным потоком; обработчики публикуют ограниченную очередь событий. Размер очереди — 4096 событий, после её заполнения новые записи пропускаются. Строки ограничены 127 символами; остальные игровые данные не записываются.

## Точки наблюдения и доказательства

Это RVA относительно загруженного SnowRunner.exe; они не считаются совместимыми с другими сборками.

- `0x10243A0`: игровая фабрика/инициализация Flash-объекта. Найдена по ссылке на диагностику `Create flash object with linkageName...`. Реальный вход восстановлен по цепочке Windows unwind metadata: запись `0x10245C2` — внутренний фрагмент, а не вход. Входные аргументы: owner и игровая строка linkage. После оригинального вызова читается значение owner+0x58. RAX передаётся обратно без изменения.
- `0x1B61880`: создание дочернего символа через ObjectInterface. Вызов из `0x1082408` передаёт interface, parent, output, linkage, instance, depth=-1, init=null. Имя экземпляра формируется как `do%d_%s`. Соседняя ветка вызывает создание пустого `flash.display.Sprite` через `0x1B61560`. Это подтверждает существование игрового пути создания display objects в AS3; само по себе не гарантирует, что символ из hud_lib доступен любому Movie.
- Наблюдаемое значение занимает 48 байт: intrusive-связи +0/+8, interface+0x10, type+0x18, object+0x20, auxiliary+0x28. Это установлено из кода копирования/освобождения, а не взято из произвольной версии SDK. Режим только observer читает его через ReadProcessMemory и не вызывает refcount-функции.
- Дополнительные точки для TEST: GetMember `0x1B5D4B0`, SetMember `0x1B5D870`, Invoke `0x1B5DCB0`, Release `0x1B5D0F0`, CreateEmptyMovieClip/Sprite `0x1B61560`. Адреса связаны с тем же строгим хешем EXE; перед запуском также сверяются префиксы функций.

В режиме TEST временные значения освобождаются в том же потоке, где созданы; управляемые ссылки между кадрами не сохраняются. Повторную попытку на том же родителе блокирует обработчик чтения ручника. Вызовы `getChildByName`, `gotoAndStop` и `removeChild` исключены. При неудаче построения прототип пытается скрыть частичную строку через свойство `visible`; она остаётся дочерним объектом до уничтожения HUD. Это не полное удаление, но не требует неподтверждённого Invoke. Тесты проверяют однократность попытки, освобождение временных ссылок, скрытие незавершённой строки и отсутствие Invoke.

`kind=3` сообщает `TEST-disabled`, `TEST-await-brake-read` или `TEST-result`. У последнего поле `type` обозначает этап: 1 — нет панели; 2 — нет ручника; 3 — не получены координаты; 4 — зарезервировано (старое значение Existing); 5 — не создан контейнер; 6 — ошибка сборки и попытка скрытия; 7 — строка создана. `kind=4` записывает собственные вызовы GetMember игрой для `rightHudPanelContainer`, `brakeBtn`, `wdBtn`, `diffBtn`, `gearBox` и их результат. В режиме наблюдения поле `ok` у `kind=1` не используется; успех присоединения символа отражает `kind=2`.

`kind=5` — контрольные точки собственных UI-операций: `UI-get.begin/end`, `UI-set.begin/end`, `UI-invoke.begin/end`, `UI-sprite.begin/end`, `UI-attach.begin/end`, `UI-release.begin/end`. Поле `instance` содержит имя свойства, метода или символа, поле `ok` у `.end` — результат. Последняя `.begin` без соответствующей `.end` помогает локализовать незавершённый вызов. Очередь обрабатывается фоновым потоком раз в 250 мс; при мгновенном завершении процесса последние события могут не попасть на диск.

Полный разбор и границы достоверности: `docs/scaleform-integration-analysis.md`.

## Следующий рубеж

Первый запуск подтвердил работу обоих перехватов и успешное создание AS3-символов игрового интерфейса на одном потоке (в частности `DefaultMouseCursor`, `in_game_layer`, `hud_interaction_option`). Он завершён до загрузки автомобильного HUD, поэтому наличие TEST ещё не подтверждено.

Второй запуск подтвердил успешное создание `defaultHud`, причём его создал другой поток, чем меню первого этапа. Вызов цепочки построения TEST сразу после этой фабрики не завершился; пользователь подтвердил зависание/сбой. Точный сбойный вызов не локализован, поэтому нельзя считать подтверждёнными ни достаточную готовность HUD в этом callback, ни весь восстановленный ABI. Все дополнительные входы в VM из этого callback удалены. Версия 3 наблюдает GetMember, не вызывает его самостоятельно.

Версии 4 и 5 подготовлены без нового запуска игры по просьбе пользователя. Собственные UI-операции выполняются только при явно включённом TEST, синхронно после успешного штатного чтения ручника. Есть защита от рекурсии и повторных попыток на том же родителе; между вызовами сохраняется лишь числовой идентификатор попытки, а не удерживаемая ссылка. Без проверки в игре эта точка остаётся кандидатом, а не подтверждённой безопасной интеграцией.

В живом тесте версии 5 подтверждены штатные чтения `gearBox`, `diffBtn`, `wdBtn`, `brakeBtn` от одного родителя, а также успешные собственные GetMember для `x` и `y` ручника. Затем `UI-invoke.begin getChildByName` не получил соответствующего end. Это локализует незавершённый вызов, но не устанавливает его внутреннюю причину. Версия 6 исключает все Invoke и проверяется отдельно.

Далее нужны результат TEST, проверка движения и жизненного цикла. Только после этого подключать состояние автопилота. Записанные адреса не использовать после удаления объекта или в другом запуске. Собственные UI-операции из потока журнала или callback создания HUD запрещены.

Версия 6 в живом тесте: собственные GetMember x/y, создание Sprite, SetMember x/y/mouseEnabled/mouseChildren, скрытие неполной строки и освобождение ссылки завершились успешно. AttachMovie(hudBtnBg) вернул false. Причина отказа символа не доказана; потеря библиотечного контекста в новом встроенном Sprite — проверяемая гипотеза. Прямое добавление целой строки в родительский MovieClip в версии 7 должно проверить эту гипотезу.

Версия 7 проверена в живой игре: пользователь видит TEST; журнал подтверждает успешное создание hudBrakeBtn, замену label/текста, отключение мыши/tab-фокуса, скрытие унаследованных значка/подсказки и освобождение временных ссылок. TEST-result=7, ok=1. Сейчас проверяются совместное движение и скрытие/возврат с картой. Подключение управления газом — отдельный следующий этап.
