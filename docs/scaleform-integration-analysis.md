# Встраивание строки автопилота в штатный HUD SnowRunner

Дата: 2026-11-07. Цель: анализ, без изменения установленной игры или кода управления.

## Вывод

Встраивание технически правдоподобно: в ресурсах установленной игры найдены AS3-классы штатных строк, фон с состояниями и общий анимируемый контейнер. Предпочтительный путь — создавать новую строку внутри существующего дерева HUD через игровой мост C++/Scaleform. Управление газом остаётся в ASI. После анализа начат отдельный прототип: восстановлены функции создания и доступа к полям, живой запуск подтвердил создание AS3-символов. Создание TEST внутри автомобильного HUD ещё требует проверки на загруженном сохранении.

## Прогресс прототипа

Исходники: `ingame/experimental/scaleform`, отдельная ветка `codex/scaleform-prototype`. Релизный автопилот не заменяется. Диагностический ASI проверяет полный SHA256 EXE и префиксы функций; при несовпадении перехваты не устанавливаются.

По ссылке на сообщение об ошибке linkageName и chained unwind metadata найден настоящий вход игровой фабрики: RVA `0x10243A0`. Внутренний RVA `0x10245C2` нельзя использовать как вход. Создание дочернего символа — RVA `0x1B61880`; создание пустого Sprite — `0x1B61560`. Также восстановлены GetMember `0x1B5D4B0`, SetMember `0x1B5D870`, Invoke `0x1B5DCB0`, Release `0x1B5D0F0`. Эти адреса относятся только к указанному EXE.

Первый запуск игры с observer подтвердил успешное создание `DefaultMouseCursor`, `in_game_layer`, `hud_interaction_option` и других AS3-символов. Оба перехвата установлены, чтение linkage/instance и 48-байтного значения соответствует фактическому журналу. Сохранение в этом запуске не загружалось.

Подготовлен прототип построения строки из пустого Sprite и нативных `hudBtnBg`/`hudBtnText`, текста TEST с выключенной обработкой мыши. Диагностическое смещение — два шага выше ручника. Однако живой тест версии 2 не завершил вызов построения после создания defaultHud: пользователь подтвердил зависание/сбой. Причина пока не локализована; потенциальны преждевременный вход в VM на загрузочном потоке и несовместимость части ABI. Наличие фабрики и совпадение имён ещё не означают безопасную готовность дерева HUD.

В версии 3 все собственные VM-вызовы из callback создания удалены. Добавлен read-only перехват GetMember, который записывает штатные обращения игры к правой панели и её кнопкам. `EnableTestRow` сейчас не запускает построение. Проверки: 21 чтения/передачи аргументов и результатов; 91 моделируемая проверка UI-вызовов/ссылок/повторного создания/отката. Моделируемые тесты не заменяют живую проверку ABI. Следующая задача — получить стабильный журнал чтений HUD и найти безопасную точку обновления.

2026-11-08: по просьбе пользователя живые проверки остановлены, диагностический ASI/INI/журнал перенесены из игры в резервную папку `ingame/build`. Рабочий автопилот соответствует последней релизной сборке. Версия 4 разработана без запуска игры: создание TEST перенесено в обработчик после успешного штатного чтения `brakeBtn`, за переключателем `EnableTestRow=1`; по умолчанию только наблюдение. Добавлены защита от рекурсии и ограничение повторных попыток. Точка пока не проверена в игре и не считается устранением исходной причины сбоя. Если игра не выполняет ожидаемое чтение, строка не создастся. Пакет прототипа подготовлен отдельно и автоматически в игру не устанавливается.

## Что проверено локально

- Установка: Epic Games / SnowRunner 44.1, `D:\Games\SnowRunner\en_us\Sources\Bin\SnowRunner.exe`.
- SHA256 EXE: `a3cb442ec138eb2eb7e335e5c80e376766550740e49e233ac9eace035e182285`.
- В `en_us\preload\paks\client\gfx.pak` есть `[gfx]/gfxbundle.gfxbundle`, 58 055 068 байт. Кэш исследуемого bundle совпадает с установленным побайтово по SHA256.
- Bundle имеет заголовок `S3DB`; это дополнительная упаковка ресурсов, а не отдельный обычный SWF.
- `hud_lib.gfx`: сцена 1920×1080, `FileAttributes=0x8`, тег `DoABC`, ABC 46.16 — ActionScript 3. `in_game.gfx` также содержит AS3. Суффикс GFX и версия заголовка сами по себе не определяют точную версию SDK.
- Таблица SymbolClass содержит `defaultHud`, `rightHudPanelCont`, `hudBrakeBtn`, `hudWdBtn`, `hudDiffBtn`, `hudBtnBg`, `hudBtnText`.
- В ABC найдены `__animFactory_rightHudPanelContaineraf1`, массивы `mat3DVec`/`matArray` и `__motion_rightHudPanelContaineraf1`. Это сильное свидетельство 3D-анимации контейнера. Как именно игра изменяет её при езде, статический разбор не устанавливает.
- В EXE найдены сообщения игрового механизма создания Flash-объекта по `linkageName`, а также предупреждения `ExternalInterface`. Их наличие даёт точки для поиска перекрёстных ссылок, но не доказывает готовый публичный API.
- EXE экспортирует 371 имя, включая 201 с `Scaleform`; среди экспортов не найдены `CreateObject`, `GetVariable`, `Invoke`, `Advance`, `CreateInstance`, `MovieImpl`, `CreateMovie`. Простого GetProcAddress для этих методов нет. Отдельной Scaleform DLL в таблице импортов EXE нет.

## Подтверждённая структура ресурса

Это структура символов из файла, а не проверенный абсолютный путь живого GFx::Movie:

```text
defaultHud
└─ rightHudPanelContainer : rightHudPanelCont
   ├─ brakeBtn : hudBrakeBtn       x=0, y=8
   ├─ wdBtn : hudWdBtn             x=0, y=56
   ├─ diffBtn : hudDiffBtn         x=0, y=104
   ├─ gearBox                     x=0, y=146
   └─ hintAnim                    x=8, y=-80
```

Шаг основных строк — 48 локальных единиц. Новая строка на один шаг выше ручника должна начинаться с `y = brakeBtn.y - 48`, то есть −40 в исходном ресурсе. Следует использовать актуальную локальную позицию экземпляра и проверить пересечения с `hintAnim`, подсказками и индикатором сохранения.

У `hudBrakeBtn` есть дочерние `btnBg`, `hitArea`, `iconContainer`, `tfCont`, `buttonAttach`. Текст находится в `tfCont.tf`; подсказка клавиши размещена около x=207, y=8. Фон `hudBtnBg` содержит метки `none`, `activate`, `warning`, `disactivate`; кнопки — `up`, `over`, `down`, `disabled`, `selected_*`, `toggle`. Это полезные кандидаты для оформления, но соответствие состояния автопилота этим кадрам ещё нужно проверить в живом HUD.

## Рекомендуемая архитектура

1. Найти игровой объект, владеющий HUD Movie, и вызов обновления/создания Flash-элементов. Начать с ссылок на диагностические строки создания по linkageName и проверки их вызывающего кода.
2. В потоке обновления интерфейса получить живой экземпляр `defaultHud` и его правый контейнер. Проверить классы и наличие `brakeBtn`, `wdBtn`, `diffBtn`; не принимать схожий контейнер iOS за основной.
3. Создать новый AS3 display object через существующую фабрику игры либо доступный AS3 domain. Добавить его в `rightHudPanelContainer` через `addChild`/`addChildAt`. Вариант с собственным нейтральным MovieClip и экземплярами штатных фона/текста предпочтительнее полного копирования кнопки с игровыми обработчиками.
4. Использовать нативный фон, текстовый стиль и подсказку клавиши. Иконку автопилота можно создать отдельно как собственную графику. Не подменять действующий `brakeBtn` и не заимствовать его события тормоза.
5. Отключить мышь и фокус только у своей строки (`mouseEnabled`, `mouseChildren` и связанные свойства после проверки), не менять настройки родительского контейнера. Не ставить `enabled=false` вслепую: CLIK может переключить оформление в disabled.
6. Из существующего CruiseState передавать только состояние отображения и выбранную клавишу. Клавиатурный поток публикует данные, UI-поток применяет их; не вызывает Scaleform напрямую из keyboard hook или Present.
7. Обрабатывать создание, удаление и пересоздание HUD при загрузке, гараже, карте, меню, смене машины/разрешения. Ссылки на старые GFx-объекты освобождать до уничтожения Movie.
8. После проверки жизненного цикла убрать распознавание изображения из нового способа отображения. Разрешение нового включения должно опираться на проверенное игровое состояние управления, а не только на существование контейнера. Потеря UI-объекта сама по себе не отменяет активное удержание газа.

Новая строка унаследует трансформацию, перспективу и скрытие родителя. Отдельные анимации состояния каждой кнопки и правила видимости её детей автоматически не наследуются: их необходимо согласовать отдельно. Поэтому обещать точное совпадение всех эффектов до прототипа нельзя.

## Особенности AS3 и ABI

- `attachMovie`/`duplicateMovieClip` — не подходящий план для этого AS3 HUD; пример из старого AS2 API нельзя переносить напрямую.
- Для AS3 нужны создание экземпляра класса и `DisplayObjectContainer.addChild`. Возможность создать пользовательский linkage-класс через конкретный GFx API и доступность его ApplicationDomain проверяются на этой сборке; публичная документация CreateObject не гарантирует доступ ко всем игровым классам.
- Вызовы Invoke/GetVariable и обновление display list должны быть синхронизированы с Movie::Advance. Текущий DirectX Present hook не является подтверждённым местом для таких операций.
- Версия Scaleform, расположение GFx::Value, vtable, правила refcount и сигнатуры игровых обёрток пока не установлены. Подключить произвольные заголовки SDK и вызывать предполагаемые адреса нельзя считать совместимым решением.
- Текущий мод собран GCC, игра использует MSVC-окружение. Для моста потребуются проверенные ABI-обёртки либо совместимая MSVC-сборка; совместимость сложных C++ классов и менеджеров памяти нельзя предполагать.

## Сравнение путей

| Путь | Что даёт | Основная сложность |
| --- | --- | --- |
| ASI создаёт строку в существующем HUD | Общая перспектива/анимация, использование установленных ресурсов, потенциально без правки PAK | Поиск Movie, фабрики, ABI и UI-потока; сопровождение после обновлений |
| Локальный патч hud_lib.gfx / gfxbundle | Добавление своего AS3-кода и элемента непосредственно в ресурс | Перепаковка S3DB, GFX-расширения, связь с ASI, конфликты с UI-модами и обновлениями |
| Отдельный SWF/GFX Movie, рисуемый движком | Scaleform-отрисовка собственной панели | Сам по себе не наследует движение и видимость правого HUD; цель решена лишь частично |

Первый путь рекомендуется исследовать первым. Если фабрика не позволяет создать подходящий класс, возможен гибрид: небольшой собственный AS3-мост/ресурс и ASI-передача состояния. Он всё равно должен добавлять строку в существующий контейнер, а не создавать второй независимый HUD.

При ресурсном пути формат GFX может содержать нестандартные теги и внешние ссылки на текстурные атласы. Сохранение через обычный SWF-редактор нельзя считать корректным без проверки повторного чтения игрой. Не подтверждены также загрузка loose-файлов и порядок переопределения ресурсов через mod.pak; их нельзя закладывать в установщик как известный механизм. Предпочтительно распространять собственный код/патч с проверкой хеша исходного ресурса, а не весь модифицированный игровой архив.

## Следующий проверяемый прототип

Сначала диагностический ASI фиксирует создание/уничтожение нужного Movie и успешно читает экземпляр `brakeBtn`. Затем добавляет одну неинтерактивную строку «TEST» в общий контейнер. Критерий успеха: одна строка, совместная перспектива и движение, сохранённый интервал, корректное исчезновение/возврат при меню, карте, гараже и загрузке, отсутствие вмешательства в ручник/полный привод/дифференциал. Только после этого подключать состояние автопилота и F6.

Для поддержки следующих версий нужны проверка EXE/ресурсов и валидируемые сигнатуры, а не фиксированные адреса. При несовместимой версии нативный backend не должен изменять UI; текущий ImGui backend можно оставить отдельно выбираемым запасным вариантом.
